# ETL Studio

Веб-инструмент для трансформаций данных: граф узлов, настоящий SQL и совместная работа
в реальном времени — как Loginom или KNIME, но целиком в браузере и без сервера.

| Задача | Решение | Почему так |
|---|---|---|
| Трансформации данных | DuckDB-WASM (SQL в браузере) | Никакого бэкенда и расходов: данные не покидают машину, доступны join'ы, группировки, оконные функции |
| Граф узлов | React Flow | Стандарт для node-based редакторов: drag, связи, миникарта |
| Совместное редактирование | Yjs + y-webrtc | CRDT поверх WebRTC: курсоры и присутствие в реальном времени, свой сервер не нужен |
| Версии | GitHub Contents API | Каждое сохранение — коммит; история и diff живут в git, а не в самодельном undo |
| Хостинг | GitHub Pages | Статика, бесплатно, ссылка живёт без вашей машины |

## Как пользоваться

1. **Узлы.** «Источник CSV» — загрузите файл или вставьте текст. «SQL-трансформация» — запрос
   к таблицам входных узлов. «Просмотр / экспорт» — результат и кнопка «Скачать CSV».
2. **Связи.** Потяните от правого кружка узла к левому кружку следующего.
3. **Имя таблицы** узла — то, как на него ссылаться в SQL ниже по графу
   (узел `sales` виден в SQL как `FROM sales`).
4. **Выполнить** — считает узлы в порядке зависимостей. Ошибка в узле не останавливает
   остальные: зависящие помечаются как пропущенные, независимые считаются.

## Совместная работа

Кнопка **«Ссылка для совместной работы»** копирует адрес с именем комнаты:

```
https://<адрес>/#room=my-team
```

Откройте его у второго участника — он увидит тот же граф, ваши курсоры с именами и будет
редактировать его вместе с вами. Комната — это просто строка в адресе, регистрации нет.

- Синхронизация идёт **напрямую между браузерами** (WebRTC); публичные сигнальные серверы
  нужны только для знакомства участников.
- Две вкладки одного браузера синхронизируются даже без интернета — через BroadcastChannel.
- Индикатор справа сверху: зелёный — сигналинг есть, серый — только локальные вкладки.
- Через строгий NAT/корпоративный файрвол прямой канал может не встать (TURN-сервера нет).

## Версии в git

Кнопка **«Версии (GitHub)»**:

- владелец / репозиторий / ветка / путь к файлу рабочего процесса;
- **fine-grained токен** GitHub с правом `Contents: Read and write` на этот репозиторий;
- «Сохранить в GitHub» — коммит с вашим сообщением;
- «История» — коммиты по этому файлу, у каждого кнопки «Восстановить» и «diff».

Токен хранится **только в localStorage браузера** и уходит напрямую в `api.github.com`.
В сборку он не попадает, на сервере его нет, отзывается в настройках GitHub.

## Локальный запуск

```bash
npm install
npm run dev        # http://127.0.0.1:5173
npm run build      # статика в dist/
```

## Ограничения, о которых лучше знать сразу

- Данные источника живут в общем документе (CRDT): CSV на много мегабайт синхронизировать
  не стоит — держите в узле выборку, а не выгрузку на миллион строк.
- Результаты выполнения **не** синхронизируются: это локальный кэш каждого браузера.
- Сборка использует одноthreadный бандл DuckDB-WASM: многопоточному нужны заголовки
  COOP/COEP, которых GitHub Pages выдавать не умеет.
